# ADR-0017 접근 코드 잠금 알림은 텔레그램으로 — 잠금 해제·잠금이 걸린 순간만, 가린 IP, 요청과 떼어 보냄

## 배경
공개 데모는 접근 코드를 받은 사람만 들어옵니다(ADR-0013). 코드는 지원한 회사별로 나눠 주는데, 누가 언제 열었는지는 서버 로그
(`security-event gate-unlocked code=이름`)를 내려받아야 알 수 있었습니다. 운영자가 폰으로 바로 알고, 무차별 대입으로 잠금이 걸린 것도 알고 싶습니다.
다른 포트폴리오 서비스 앞단(gate)과 같은 사건·형식으로 맞춥니다.

## 선택지
1. 알리는 때: 매 요청(잠금화면·API 포함) / **잠금 해제 성공(같은 IP 는 1시간에 한 번) + IP 잠금·전체 잠금이 새로 걸린 순간** —
   매 요청이면 쿠키 12시간 동안 화면 이동마다, 잠긴 동안의 거절마다 보내면 대입 시도 한 번에 알림이 수십 건 쌓입니다.
2. IP: 전체 IP / **가린 IP(IPv4 앞 세 자리, IPv6 /48)** — 알림은 외부(텔레그램)에 남으므로 어느 곳에서 들어왔는지 짐작할 만큼만 보냅니다.
   전체 IP 는 지금처럼 서버 로그에만 있고, 중복 판단 키도 서버 메모리 안의 전체 IP 입니다.
3. 전송: 요청 스레드에서 동기 / **작업자 스레드 하나 + 큐 50건(넘치면 버림), 재시도 없음(429 포함)** — 텔레그램이 느리거나 막혀도
   잠금 해제·차단 응답이 늦어지거나 바뀌지 않습니다. 알림은 놓쳐도 되는 부가 기능입니다.
4. HTTP 클라이언트: 텔레그램 봇 라이브러리 / **JDK HttpClient** — 쓰는 API 가 `sendMessage` 하나라 라이브러리를 더할 이득이 없습니다.

## 결정
- `GateNotifier`(global.gate). 잠금이 켜져 있고(`GATE_CODES`) `TELEGRAM_BOT_TOKEN`·`TELEGRAM_CHAT_ID` 가 모두 있을 때만 켭니다. 하나만 있으면 끄고
  기동 로그에 어떤 이름이 비었는지만 남깁니다.
- 시도 제한은 해시 계산 전에 실패로 세며 잠금을 미리 걸고 맞으면 되돌리므로(ADR-0013, M-1), 잠금 알림은 틀린 코드로 확정된 시도에서만 보냅니다.
  맞는 코드로 되돌린 잠금은 알리지 않습니다. 시도 제한의 동작(잠금 시점·응답 코드·문구·쿠키)은 바꾸지 않았습니다.
- 평문(parse_mode 없음)·링크 미리보기 끔, 시각은 KST. 기기는 User-Agent 를 "브라우저 · OS" 로 줄여 보내고 원문은 보내지 않습니다.
- 잠금 해제 알림은 모든 IP 를 합쳐 10분에 10건까지 — 코드를 가진 사람이 IP 를 바꿔 가며 풀어도 쌓이지 않게. 넘친 것·큐가 차 버린 것은 기억하지 않고
  세어 두었다가 다음 해제 알림에 "그 사이 알리지 못한 잠금 해제 k건" 으로 덧붙입니다(잠금 알림은 시도 제한이 이미 묶어 상한 없음).
- 6to4(2002::/16) 주소는 /48 안에 IPv4 가 통째로 들어 있어 IPv4-mapped 처럼 그 IPv4 의 앞 세 자리로 가립니다. Teredo 는 /48 로 드러나지 않아 IPv6 /48 그대로입니다.
- 봇 토큰이 요청 주소에 들어가므로 주소·토큰·대화 ID 는 로그·예외 메시지·toString 에 남기지 않습니다. 실패는 상태 코드나 예외 클래스 이름만.
- 연결부터 응답 본문까지 전체 5초(JDK 요청 시간 상한은 응답 헤더까지만 세서, 헤더 뒤 본문이 멈추면 작업자가 묶이므로 교환 전체를 끊음). HttpClient 의 실행기는 스레드 1개로 지정합니다(기본값은 필요한 만큼 늘림, App Service B1 은 CPU 1개).
  작업자 스레드와 나누면 작업자가 응답을 기다리는 동안 응답 처리가 같은 스레드를 기다려 멈추므로 따로 둡니다. 두 스레드는 쉬면 60초 뒤 사라지고,
  알림을 켜면 HttpClient 가 연결을 살피는 스레드(SelectorManager) 하나를 계속 둡니다.
- 빈으로 만들어 앱이 멈출 때 큐에 남은 알림을 최대 5초 기다린 뒤 닫습니다.

## 결과
- 코드를 받은 사람이 들어오면 운영자가 어느 코드로 들어왔는지 바로 압니다. 대입 시도도 잠금이 걸린 순간 압니다.
- 외부(텔레그램)로 나가는 정보는 서비스·코드 이름·가린 IP·브라우저/OS 요약뿐입니다.
- 중복 억제가 인메모리라(IP 1000개까지) 재시작하면 같은 IP 도 다시 알리고, 인스턴스 1개 전제입니다(ADR-0013 과 같음).
  큐가 차거나 전송이 실패한 알림은 사라집니다 — 서버 로그의 security-event 는 그대로 남습니다.
- 근거: `GateNotifierTest`(형식·KST·IP 가리기·User-Agent 표·1시간 억제·해제 알림 전체 상한·켜는 조건·실패 무시·큐 상한·비밀값 가림·환경변수 연결·HTTP 전송부와 시간 상한),
  `AccessGateFilterTest`(해제 성공 1번·5번째 실패에서 1번·전체 잠금 1번·되돌린 잠금은 없음·전송 실패에도 응답 그대로).
