# 2차 점검 — 시스템(아키텍처·성능·보안)과 UI/UX (2026-09-28)

1차 코드 리뷰([REVIEW_2026-09](REVIEW_2026-09.md)) 뒤, 전산 전공자·풀스택 시니어 개발자의 기준으로 다시 점검한 기록입니다.

- **아키텍처**: 계층 분리와 의존 방향, 결합·순환·중복, API 일관성(URL·메서드·상태 코드·오류 형식), 설정 분리, 예외 처리·로깅
- **성능**: N+1·중복 쿼리, 인덱스, 페이지네이션 없는 전체 조회, 캐싱, 불필요한 렌더링·중복 호출, 번들, 블로킹 I/O, 누수, 알고리즘
- **보안**: OWASP Top 10 — 인젝션, XSS, CSRF, 인증·인가, 세션·토큰, 비밀번호 저장, 입력 검증, 비밀값, CORS·보안 헤더, 오류 응답, 로그 속 민감정보, 취약한 의존성
- **UI/UX**: 접근성(WCAG 2.1 AA), 오류·빈 화면, 안내 문구

결함은 "재현 → 원인 → 실패하는 테스트 → 수정 → 재검증" 순서로 처리했고, 성능 수치는 측정값만 적었습니다.
**결과: 발견 19건 모두 해결** (PR A 보안·운영 6 / PR B 성능·API 5 / PR C UI/UX 7 / PR D 폴더 휴지통 1 — 소유자 결정). 남은 위험은 §4.

## 3. 변경 기록

### PR A — 보안·운영

#### SEC-10 요청 본문 크기 제한
- **재현**: `POST /api/public/shares/{token}/unlock` 에 10MB·60MB JSON → 끝까지 읽은 뒤 404(0.4초·1.5초). 공개 경로라 CSRF 도 없고, 로그인도 필요 없습니다.
- **수정**: `RequestBodyLimitFilter`(보안 필터보다 먼저)가 `Content-Length` 가 한도를 넘으면 읽기 전에 413, 길이를 알리지 않는 전송(chunked)은 읽는 도중 한도를 넘는 순간 413. 파일 업로드(multipart)는 기존 업로드 한도를 따릅니다. 한도는 `app.http.max-body-size`(기본 6MB) — 텍스트 편집 저장(2MB)이 JSON 이스케이프로 커져도 여유가 있습니다.
- **검증**: `RequestBodyLimitTest` 4건(실제 Tomcat, 수정 전 2건 실패 → 통과).

#### SEC-07 사용자별 하루 번역 분량
- **문제**: DeepL 무료 요금제는 월 50만 자인데, 1회 최대 5만 자 번역을 사용자별 제한 없이 허용해 한 사람이 약 10번 만에 서비스 전체의 한 달 번역을 멈출 수 있었습니다.
- **수정**: 요청 제한기에 무게(글자 수)를 매기는 `tryAcquire(key, weight, limit, window)` 를 추가하고, `TranslationService` 가 사용자별 24시간 번역 글자 수(기본 10만 자)를 넘으면 429. 번역 비활성·문서 초과로 거절되는 요청은 분량을 쓰지 않습니다. DeepL 의 월 한도 초과(456)는 일반 오류가 아니라 한도 초과로 안내합니다.
- **자체 검증에서 잡은 회귀**: 처음 구현은 "번역 설정 확인"을 권한 확인보다 먼저 해, 남의 파일에 번역을 요청하면 404 대신 503 이 나왔습니다(설정 정보가 권한 확인보다 먼저 드러남). 기존 `AccessControlTest` 가 잡았고, 권한 확인(문서 읽기)을 가장 먼저 하도록 고친 뒤 단위 테스트도 추가했습니다.
- **검증**: `TranslationServiceTest` 5건, `SlidingWindowRateLimiterTest`(무게 제한), `DeepLTranslationClientTest`(456).

#### ARC-02·SEC-11 요청 추적과 보안 이벤트 기록
- **수정**: `RequestTraceFilter`(가장 먼저 실행)가 요청마다 추적 ID 를 정해 MDC·응답 헤더 `X-Request-Id`·오류 본문 `requestId` 에 남깁니다. 앞단 프록시가 준 ID 는 `[A-Za-z0-9._-]{8,64}` 일 때만 이어 씁니다(줄바꿈을 넣어 로그를 위조하지 못하게). API·WebSocket 요청마다 한 줄 접근 기록(메서드·경로·상태·소요 시간·사용자 ID·IP)을 남기되, 쿼리 문자열은 공유 다운로드 허가처럼 비밀값이 들어갈 수 있어 남기지 않습니다. `SecurityEventLog`(`security` 로거)는 로그인 성공·실패, 요청 제한 발동, 공유 비밀번호 실패를 기록합니다 — 입력한 아이디·비밀번호·공유 토큰은 남기지 않습니다(아이디 칸에 비밀번호를 잘못 넣는 일이 흔함).
- **예**: `[56364498…] c.s.global.web.RequestTraceFilter : GET /api/auth/me 401 0ms user=- ip=127.0.0.1`
- **검증**: `RequestTraceTest` 4건.

#### SEC-12 CSP 에서 인라인 스타일 금지
- **수정**: `style-src 'self'`. 앱의 `style` 속성(메뉴 위치·진행률 막대 등)은 React 가 DOM API(CSSOM)로 적용하므로 CSP 의 영향을 받지 않습니다.
- **검증**: E2E 공통 fixture 가 모든 페이지(다른 사용자·비로그인 페이지 포함)의 CSP 위반 보고를 모아 하나라도 있으면 실패하게 했고, 8개 시나리오에서 위반 0. E2E 가 다루지 않는 작업 메뉴·이동 대화상자도 확인했고, 인라인 `<style>` 을 일부러 넣으면 차단·보고되는 것(감시가 실제로 동작함)도 확인했습니다. `SecurityHeadersTest` 추가.

#### ARC-05 구조 규칙을 테스트로 고정
- `ArchitectureTest`(ArchUnit): 컨트롤러 → 리포지토리 직접 사용 금지, 서비스의 서블릿 타입 의존 금지, 컨트롤러의 엔티티 응답 금지, `global`·`storage` 의 도메인 패키지 의존 금지. 지금 구조가 이미 지키고 있는 규칙을 기능 추가 중에 무너뜨리지 않기 위한 장치입니다.

#### 함께 바로잡은 문서
- 테스트 프레임워크는 실제로 **JUnit 6.0.3** 인데 문서에는 "JUnit 5" 로 적혀 있었습니다(의존성 조회로 확인).

### PR B — 성능·API

#### PERF-02 항목이 많은 폴더
- **측정**: 서버 목록 API 는 5,000개에 76~86ms 로 병목이 아니었고, 화면이 전부 그리느라 느렸습니다(5,000개 첫 표시 1.45초·정렬 0.19초·전체 선택 0.20초·힙 123MB).
- **수정**: `FileTable` 이 앞에서부터 200개씩 그리고, 목록 끝이 보이면(IntersectionObserver) 또는 "나머지 N개 더 보기"로 이어서 그립니다. 선택·정렬·Ctrl+A 는 전체 목록 기준이고, 키보드로 마지막 행에서 아래로 가면 다음 묶음을 그려 이어서 이동합니다. 서버 페이지네이션은 정렬 네 가지를 서버로 옮겨야 하는데 서버가 병목이 아니어서 택하지 않았습니다.
- **결과**(`e2e/scripts/measure-large-folder.mjs`, 3회): 5,000개 첫 표시 **0.17~0.22초**, 정렬 **0.02~0.03초**, 전체 선택 **0.02~0.05초**, 힙 **24~37MB**. 실제 브라우저에서 스크롤하면 200 → 400 → 600 → 650행으로 이어지는 것도 확인.
- **검증**: `FileTable.test` 4건.

#### PERF-03 여러 항목 삭제
- **수정**: `POST /api/items/delete` — 한 트랜잭션(하나라도 지울 수 없으면 아무것도 지우지 않음), 중복 항목은 하나로, 팀 변경 알림은 폴더당 한 번. 파일을 먼저 처리합니다(폴더 삭제의 일괄 DELETE 가 영속성 컨텍스트를 비우므로). 쓰이지 않게 된 화면의 단건 삭제 함수는 지웠고 서버의 단건 API 는 남겼습니다.
- **검증**: `ItemDeletionTest` 4건. 브라우저에서 5개 삭제 시 변경 요청 5 → 1.

#### PERF-04 알림 최신순 인덱스
- **재현**: 한 사용자 알림 3,000개에서 "최신순 30개"가 기존 인덱스로 사용자 알림 전체를 읽고 정렬(`Using filesort`), 2.2~2.5ms.
- **수정**: `V2__notifications_recent_index.sql` — `(user_id, created_at, notification_id)`. 결과 `Backward index scan`, 0.10~0.22ms. 기존 인덱스는 읽지 않은 수 세기에 계속 씁니다.
- **검증**: `NotificationQueryPlanTest`(실행 계획 확인, 수정 전 실패). 처음 테스트는 한 사용자의 알림이 테이블 전부라 옵티마이저가 인덱스 대신 전체 읽기를 골랐습니다 — 실제처럼 다른 사용자 데이터를 섞어 바로잡았습니다.

#### PERF-05 휴지통 자동 비우기 배치
- **수정**: 500개씩 따로 커밋하고, 실패한 배치는 기록 후 다음 배치를 계속합니다(다음 날 다시 대상). 로그에 실제로 지운 수와 배치 수를 남깁니다.
- **검증**: `TrashPurgeBatchTest`(1,100개 → 3배치).

#### ARC-03 회원 탈퇴 API
- **수정**: `DELETE /api/users/me`(본문에 비밀번호) → `POST /api/users/me/delete`. DELETE 요청의 본문은 HTTP 에 정의된 의미가 없어 프록시·클라이언트가 버리거나 거절할 수 있습니다. 탈퇴 응답은 로그아웃처럼 CSRF 쿠키도 지웁니다. 화면의 `http.del` 은 타입에서 본문을 받지 않도록 막았습니다. 공개 API 변경이지만 클라이언트는 이 저장소의 화면뿐입니다.

### PR D — 폴더 휴지통 (UX-06)

- **결정**: 폴더를 즉시 영구 삭제하던 것을 두고 선택지(폴더 휴지통 / 영구 삭제 유지 + 확인 강화 / 유지)를 소유자에게 물었고, 폴더 휴지통을 택했습니다.
- **설계**: `folders.trash_root_id`(휴지통에 들어간 트리의 맨 위 폴더, 맨 위는 자기 자신)를 하위 폴더까지 넣고 안의 파일은 그대로 둡니다. "휴지통 안인가"를 한 열로 판단하므로 트리·검색·사용량·자식 목록 쿼리는 조건 하나(`trash_root_id is null`)로 걸러지고, 휴지통 안의 폴더·파일에 대한 모든 작업은 `AccessPolicy` 한 곳에서 404 로 막힙니다(다운로드·편집·업로드·이동·복사·공유 링크·채팅 공유). 이미 따로 지운 하위 트리는 표시를 덮어쓰지 않아 휴지통에 따로 남고, 원래 상위 폴더도 휴지통이면 최상위 폴더로 복원합니다. 저장 공간 한도는 이전처럼 휴지통까지 셉니다.
- **구현 중 잡은 문제**: 영구 삭제가 409 로 실패했습니다 — 맨 위 폴더가 자기 자신을 가리키는 FK 를 InnoDB 가 지우지 못하게 막았습니다. FK(무결성)는 두고, 영구 삭제 직전에 그 트리의 휴지통 표시를 지우도록 했습니다(휴지통 비우기·자동 비우기·팀 삭제·탈퇴가 모두 같은 경로).
- **E2E 에서 잡은 테스트 문제**: 폴더를 누른 직후 폴더 화면으로 바뀌기 전에 파일을 올려 최상위에 올라가는 경합이 있었습니다(앱이 아니라 테스트의 대기 누락) — 폴더 제목(h1)이 보인 뒤 올리도록 고쳤고 3회 연속 통과를 확인했습니다.
- **검증**: `FolderTrashTest` 8건(수정 전 6건 실패, 나머지 2건은 이전 동작에서는 대상이 사라져 우연히 통과), 기존 테스트 2건을 새 동작으로 갱신(폴더 영구 삭제 FK 회귀 테스트는 휴지통을 거쳐 영구 삭제), 프론트 `TrashPage.test` 3건, E2E(폴더를 휴지통에 넣고 복원).

## 4. 남은 위험과 권장

- **로그아웃해도 JWT 가 만료 전까지 유효**: 사용자별 토큰 버전으로 무효화하면 로그아웃 한 번에 그 계정의 모든 기기가 로그아웃되는데, 여러 방문자가 함께 쓰는 체험 계정에서는 한 사람의 로그아웃이 다른 방문자를 모두 내보냅니다. 쿠키가 HttpOnly·SameSite=Strict 라 탈취 자체가 어렵고, 필요해지면 토큰 ID(jti) 폐기 목록을 권장합니다.
- **SEC-04**: v1 이력의 비밀값은 소유자가 재사용 여부를 확인하고 재발급해야 합니다(1차 리뷰와 같음).
- **운영 DB 마이그레이션**: 기동 시 Flyway 가 V2(알림 인덱스)·V3(폴더 휴지통 열 3개·인덱스·FK)를 자동 적용합니다. 둘 다 열·인덱스 추가라 기존 데이터는 바뀌지 않습니다.
