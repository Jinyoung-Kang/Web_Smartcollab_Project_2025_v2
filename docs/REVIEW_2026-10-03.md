### 1-5. 프런트엔드 구조

- **현재 상태**
  - API 호출은 모두 `src/api` 에 모여 있습니다(직접 `fetch` 0건).
  - 하지만 화면 컴포넌트가 쿼리·변경 요청·캐시 무효화·업무 규칙을 함께 갖고 있습니다.
  - 기능별 커스텀 Hook 은 0개입니다(`lib/` 의 범용 Hook 3개만 있음).
- **가장 큰 화면들**
  - `DrivePage`(323줄)는 쿼리, 변경 요청 5종, 끌어 놓기, 선택, 이동 규칙을 함께 갖고 있고 **테스트가 없습니다**.
  - `EditorPage`(305줄)는 상태 9개와 저장·충돌·이탈 방지·요약·번역을 함께 갖고 있습니다.
  - `ChatTab`(251줄)은 페이지 합치기를 키를 누를 때마다 다시 하고, 메시지 묶기 규칙을 렌더링 안에 두었습니다.
  - `TeamPanel`·`TeamActivity`·`UploadProvider`·대화상자들도 같은 상태입니다.
- **같은 규칙이 여러 벌**
  - "드라이브 변경 뒤 무효화할 캐시"가 5곳에서 서로 다르게 구현되어 있습니다(`DrivePage.tsx:79-83`, `TrashPage.tsx:30-35`, `TeamActivity.tsx:73-77`, `UploadProvider.tsx:51-52`, `ChatTab.tsx:112`).
  - 그 결과 삭제 뒤 휴지통 목록이 최대 30초 늦게 바뀝니다.

## 2. 개선 계획 (우선순위 순, 단계마다 PR 하나)

원칙:
- 버그는 실패하는 테스트로 먼저 재현하고, 증상이 아니라 원인을 고칩니다.
- 테스트가 없는 코드를 리팩터링하기 전에는 현재 동작을 고정하는 테스트를 먼저 추가합니다.
- 리팩터링과 버그 수정은 한 커밋에 섞지 않습니다.
- 커밋마다 테스트·빌드·린트·타입 검사를 통과시킵니다.
- 새 인프라(메시지 브로커·캐시 서버·마이크로서비스)나 과한 추상화 계층은 들이지 않습니다.
- 작은 중복은 그대로 둡니다.

### 단계 1 — 보안·데이터 손실 (구체 방안)

- **S-01**
  - Spring Boot 의 버전 속성으로 Jackson 3.1.7·2.22.3 을 지정합니다(패치 업그레이드).
  - Boot 4.1.2 가 나오면 이 지정을 지웁니다.
- **S-02·S-03**
  - 로그인 아이디가 가입 규칙(영문·숫자·`_ . -` 4~20자)에 맞지 않으면, 제한기에 키를 남기지 않고 바로 "아이디 또는 비밀번호가 올바르지 않습니다"로 답합니다(응답 형식은 지금과 같음).
  - 요청 DTO 에 길이 상한을 둡니다.
  - 제한기는 키마다 자기 창 길이로 정리합니다(24시간 창이 모든 키를 24시간 붙잡지 않게).
- **S-04**
  - 복사 대상의 중복을 제거합니다.
  - 한 번에 복사하는 **폴더 수 상한 1,000개**와 깊이 상한(S-05)을 둡니다.
  - 큰 IN 목록 조회는 나눠서 실행합니다.
- **S-05**
  - 폴더 생성·이동·복사에 **깊이 상한 50단계**를 둡니다(설정으로 변경 가능, MySQL 재귀 한도 1000보다 충분히 낮음).
- **S-06**
  - 폴더 구조를 바꾸는 작업(생성·이동·이름 변경·휴지통·복원)은 저장 공간 행을 잠근 뒤 다시 확인해 차례대로 처리합니다. 이 잠금은 이미 저장 한도 확인에 쓰고 있습니다.
  - 폴더 엔티티는 바뀐 열만 UPDATE 하게 합니다(`@DynamicUpdate`, **스키마 변경 없음**).
- **S-07**
  - 접근 로그에서 공유 토큰 자리를 가립니다(`/api/public/shares/***/download`).
- **S-08**
  - 수락 시점에 초대자가 아직 멤버이고 초대 권한이 있는지 다시 확인합니다. 아니면 "더 이상 유효하지 않은 초대"로 처리합니다.
  - 새 멤버의 편집 권한은 **초대자가 팀장이거나 편집 권한이 있을 때만** 켭니다.
- **S-09**
  - 링크를 쓸 때 **링크를 만든 사람이 지금도 그 파일을 공유할 권한이 있는지** 확인합니다.
  - 링크 데이터는 지우지 않습니다. 권한이 다시 생기면 다시 동작합니다.
- **S-10**
  - 한 사람이 팀장인 팀 수에 **상한 10개**를 둡니다(설정으로 변경 가능, 체험 계정은 데모 팀만).
  - 상한을 넘으면 409 와 안내 문구를 냅니다.
- **S-11**
  - WebSocket 세션당 구독 **50개 상한**을 둡니다.
  - 같은 목적지를 중복 구독하면 거절합니다.
- **S-12~S-19**
  - S-12: 파일 이름에 형식 문자(유니코드 Cf 범주)를 거절합니다.
  - S-13: `/view` 응답에 `CSP: sandbox` 를 붙입니다.
  - S-14: 운영 프로필에서 DB 접속 정보를 필수로 합니다(없으면 기동 실패).
  - S-15: 상위 폴더가 함께 선택된 하위 항목은 건너뜁니다.

### 단계 2 — 신뢰성·성능

- **P-01 (텍스트 저장)**
  - 1차 PERF-01 과 같은 방식을 씁니다. 먼저 트랜잭션 밖에서 저장소에 씁니다.
  - 그다음 짧은 트랜잭션에서 잠금, 한도 확인, 버전 저장을 합니다.
  - 실패하면 저장소에 쓴 것을 지웁니다.
- **P-02 (커밋 뒤 저장소 삭제)**
  - 커밋 뒤 저장소 삭제를 DB 커넥션을 돌려준 다음에 실행합니다.
  - 트랜잭션 밖에서 키 목록을 받아 지웁니다.
- **P-03 (텍스트 읽기)**
  - 텍스트 읽기는 권한 확인만 트랜잭션 안에서 하고, 저장소 읽기는 밖에서 합니다.
- **채택 기준:** 셋 모두 저장소 지연 테스트로 전후를 측정합니다. 개선이 측정되지 않으면 되돌립니다.

### 단계 3 — 백엔드 모듈 경계

- **목표:** 기능 패키지 구조(`auth·file·folder·team…`)와 각 패키지의 Controller → Service → Repository 계층은 유지합니다. **의존 방향을 바로잡아 순환을 끊습니다.**
  - 패키지마다 `api/application/domain` 하위 폴더를 새로 나누는 대규모 이동은 하지 않습니다. 파일 100여 개의 이동 대비 이득이 작고, 계층은 이름·어노테이션 규칙으로 테스트할 수 있습니다.
- **A-02 (연쇄 삭제)**
  - 회원 탈퇴·팀 삭제를 **트랜잭션 안의 동기 도메인 이벤트**(`AccountDeleting`·`TeamDeleting`)로 바꿉니다.
  - 각 모듈이 자기 데이터를 지웁니다. 삭제 순서는 `@Order` 로 명시합니다.
  - 기존 탈퇴·팀 삭제 테스트로 동작이 같음을 확인합니다.
  - 새 인프라는 없습니다. Spring 의 이벤트를 그대로 씁니다.
- **A-03 (도메인 이벤트 위치):** 도메인 이벤트를 중립 패키지로 옮깁니다. `realtime` 은 이벤트를 듣기만 합니다.
- **A-04 (모듈 경계)**
  - 폴더 DTO 는 `folder` 로, 권한 DTO 는 `access` 로 옮깁니다.
  - 폴더 휴지통 처리는 `folder` 모듈로 옮깁니다.
  - 루트 폴더 생성은 `FolderService` 를 거치게 합니다.
- **A-05 (웹 타입 의존)**
  - 업로드는 `UploadSource`(이름·크기·스트림)를 받게 하고, 가짜 어댑터를 지웁니다.
  - 서비스는 자기 결과 타입을 돌려주고, 컨트롤러가 응답 DTO 로 바꿉니다.
- **A-06 (권한 규칙)**
  - 흩어진 권한 규칙을 `AccessPolicy` 로 모읍니다(`requireTeamTrash`·`requireInvite`·`requireSign`·`requireTeamFile`).
- **A-07 (중복 구현)**
  - "휴지통이 아닌 파일 찾기"를 하나로 합칩니다.
  - 단건 삭제는 여러 항목 삭제 서비스를 거치게 합니다.
- **A-08 (구조 규칙 테스트):** ArchUnit 에 다음을 추가합니다.
  - ① 순환 규칙: 남는 순환을 기준선으로 얼려 새 순환을 막습니다.
  - ② 리포지토리는 자기 모듈에서만 쓰게 합니다.
  - ③ 서비스·컴포넌트가 웹 타입·컨트롤러에 의존하지 않게 합니다.
- **남을 것으로 예상되는 순환:** 엔티티 연관(파일↔폴더↔팀↔사용자)과 `AccessPolicy` 가 엔티티를 받는 데서 생기는 순환입니다.
  - 이를 끊으려면 엔티티 분리나 ID 참조 전환이 필요해 비용이 큽니다.
  - 이유를 ADR 로 남기고 기준선으로 고정합니다. 결과로 양방향 쌍 수를 전후로 보고합니다.
